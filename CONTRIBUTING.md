# Contributing to Paysim

Contributions are welcome. This page exists so that a well-written patch
does not get turned down for a rule nobody could have known about.

## What the project is for

> The goal is **not** to simulate a payment that succeeds — sandboxes
> already do that. It is to provoke, on demand, the failures a sandbox
> refuses to produce: a webhook arriving before the HTTP response, a
> delivery duplicated or out of order, a timeout in the middle of a
> capture, an abandoned 3DS, a deferred unpaid.

Every design decision is settled in favour of that sentence, and so is
every pull request. A change that makes the nominal path nicer, faster or
prettier, without giving a merchant a new way to break, is off target —
however good the code.

## Non-negotiable rules

These predate any contribution and are not up for negotiation inside a
pull request. They are what makes the chaos engine uniform and a second
provider mechanical to add; if one of them gets in your way, the design
is what we discuss, in an issue, before any code.

1. **`internal/domain` never imports `internal/providers`.** No `vads_*`
   field, no `pi_xxx` identifier, no provider vocabulary in the domain.
   `internal/arch/arch_test.go` parses the imports and fails if that ever
   changes — when it does, the design is at fault, not the test.
2. **Every webhook goes through `internal/delivery`.** No direct send from
   an adapter, not even on the nominal path.
3. **The real protocol is reproduced as it is, defects included.** We do
   not normalise it, correct it or modernise it. A fake that lies is worse
   than no fake at all.
4. **No test reaches the network.** Signature vectors come from real
   captures under `testdata/`, never generated by our own code — a vector
   produced by the implementation it is meant to verify proves nothing.
   `cmd/paysim-record` is the recording proxy that produces them. If a
   vector is missing, ask for it rather than making one up.
5. **Chaos is never on by default.** It is switched on explicitly:
   configuration, scenario, or magic value.
6. **No new external dependency without discussion** — Go or npm alike.
   The standard library is the default: `net/http` and its `ServeMux`, no
   web framework, no ORM, no assertion library. The question to answer is
   "what does it save me from writing", not "is it popular".
7. **Public URL and internal URL are two distinct settings.** One is for
   browser redirects, the other for server-to-server calls. Never derive
   one from the other, never fall back to `localhost` — that works outside
   a container and breaks inside every compose file and every cluster.
8. **Paysim runs as a single instance.** Payments, event log and delivery
   queue live in memory and are not shared. Two replicas behind a Service
   produce inconsistent results without ever raising an error.

## Getting set up

You need Go (the version pinned in `go.mod`), Node 22, and a C toolchain
for `go test -race`.

```bash
git clone https://github.com/sprimault/paysim.git
cd paysim
```

| Command | What it does |
|---|---|
| `make dev` | Backend plus front-end with HMR on http://127.0.0.1:5173 |
| `make test` | `go test -race ./...` |
| `make lint` | `golangci-lint run` |
| `make build` | Single binary, front-end embedded |
| `make web-types` | Regenerates the TypeScript types from the Go structs |

Always go through the `make` targets rather than calling `go test`
directly: they build the front-end first, which `internal/webui` embeds
via `//go:embed` and without which the Go build does not even compile.

`make web-types` matters more than it looks. The TypeScript types under
`web/src/shared/model/` are generated from the Go structs by tygo, and a
CI job fails as soon as they drift. Run it whenever you touch an exported
struct or an exported constant that the front-end consumes.

## What a pull request needs

- **One branch and one pull request per deliverable.** Base branch is
  `master`.
- **Conventional commits**: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`.
  The prefix is required; the description is preferably in French, but
  English is accepted — the prefix is what tooling reads, the description
  is what humans read.
- **Tests ship with the change.** A behaviour that is not covered is a
  behaviour that will silently regress.
- **All checks green.** Every pull request runs the Go linter, the unit
  tests with the race detector, the front-end linter and tests, a
  dependency audit, a drift check on the generated types, and the seven
  canonical scenarios against a real binary in both storage modes.
- **Commit messages say what the change does and why.** Validation and
  execution context belong in the pull request, which is written for a
  reviewer, not for whoever reads the history in two years.

Formatting, amounts and dates go through the shared helpers — `internal/format`
on the Go side, `web/src/shared/lib/` on the front-end side. Amounts are integer
cents, never floats, and are converted for display in `money.go` and
nowhere else.

## Adding a provider

Not yet. PayZen is currently the only provider, and the seam a second one
would plug into has not been carved out: `internal/api`, `cmd/paysim` and
`internal/scenarios` still depend on the `payzen` package directly. There
is no `Provider` interface to implement today.

Extracting that seam is the work of the Stripe phase, driven by the
maintainer precisely because it is the moment the abstraction gets
designed rather than guessed. This page will describe the recipe once the
recipe exists. Until then, open an issue rather than starting an adapter
that would have to be rewritten.

## Reporting a bug

The most useful reports are the ones showing that Paysim asserts something
false without signalling it — a webhook describing a card that was never
presented, a state the documentation promises and the binary does not
produce. Say what you did, what you expected from the real PSP, and what
Paysim answered.

Security flaws are the exception: they go through the private channel
described in [`SECURITY.md`](SECURITY.md), never through a public issue.
That page also states what counts as one — Paysim is permissive by
design, and most of that permissiveness is deliberate.
